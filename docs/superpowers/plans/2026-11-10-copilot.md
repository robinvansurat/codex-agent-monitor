# Copilot Session Monitoring Implementation Plan

> For agentic workers: Follow the repository's Kiro-first worker policy and preserve existing uncommitted edits.

**Goal:** Observe local Copilot Desktop, CLI and VS Code sessions using evidence-backed session, model, state and token metadata.

**Architecture:** Read shared Copilot session-state and separately verified VS Code chat formats locally. Adapt safe observations to the existing provider, snapshot and display paths; never invent missing data or merge unproven identities.

**Tech Stack:** Rust, existing serde_json, chrono and test dependencies.

**Spec:** `docs/superpowers/specs/2026-11-10-copilot-design.md`.

## Global Constraints

- No network access, credentials, message text or external mutations in monitor collection.
- Treat Gosoft model aliases as requested names, not verified upstream models.
- Support standard home, COPILOT_HOME and explicit home; show all models.
- Preserve unrelated local changes. Report unsupported or ambiguous evidence as unknown.

## Review Focus

- Concurrent deletion and incomplete last JSONL records must not abort collection or produce false state.
- VS Code mutation records and mixed-provider sessions must not cause fabricated Copilot sessions or leak message content.
- A crash after a start event must not imply indefinitely running work.
- Context occupancy and per-call metrics must not be mislabeled cumulative session usage or double counted.
- Cross-source IDs must only be merged when their identity is verified.
